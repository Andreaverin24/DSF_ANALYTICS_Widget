## Локальный ключ

`scripts/Build-Release.ps1` использует `.signing/dsf-finance.p12`, alias `dsf-finance`, RSA 4096. Каталог исключён из Git; доступ ограничен текущим пользователем Windows и SYSTEM. Пароль хранится в `.signing/password.dpapi.xml`, зашифрованном Windows DPAPI. Его нельзя публиковать или выводить в консоль. Оба файла уже созданы; не генерировать новый ключ и не запускать повторную инициализацию.

Повторная сборка тем же ключом:

```powershell
.\scripts\Build-Release.ps1
```

Скрипт собирает release и выполняет Android Lint и unit-тесты debug-варианта. Gradle запрещает release без явно переданных данных подписи, fallback на debug отсутствует. APK ожидается в `app/build/outputs/apk/release/app-release.apk`. Перед размещением обязательны проверка `apksigner verify --verbose --print-certs`, package `finance.dsf.widget`, versionName/versionCode, отсутствие debuggable и SHA-256 файла. Отпечаток сертификата фиксируется после проверки APK, без приватного ключа.

У установленного тестового APK (сейчас debug 0.3.9) другая подпись. Публичный release нельзя установить поверх него как обычное обновление. Не удалять приложение/виджет на телефоне автоматически. Последующие публичные версии должны использовать один и тот же release-ключ и возрастающий versionCode.

## Переносимая резервная копия

Копия `.signing` сама по себе не обеспечивает перенос на другую Windows: DPAPI привязан к учётной записи и среде. Для защиты от потери текущего компьютера владельцу следует сохранить переносимый ключ с отдельным известным ему паролем:

```powershell
.\scripts\Export-SigningBackup.ps1 -Destination 'D:\PRIVATE_BACKUP\dsf-finance-signing.p12'
```

Путь приведён как пример; каталог должен существовать и находиться вне web/public, репозитория и общедоступных папок. Скрипт интерактивно дважды запрашивает пароль, не выводит его, экспортирует тот же ключ и проверяет alias. Существующий файл не перезаписывается. Пароль сохранить в менеджере паролей отдельно от резервной копии. Переносимый экспорт с паролем владельца ещё не выполнен; проверка восстановления временной копии описана ниже.

Проверка восстановления: на отдельной закрытой копии импортировать резервный PKCS12 под новым локальным паролем, сверить SHA-256 сертификата с опубликованным, затем подписать тестовый APK этим ключом и проверить сертификат через `apksigner`. Пароли вводить интерактивно или передавать через process environment, не через аргументы командной строки. Рабочую `.signing` при проверке не заменять. Успешное чтение alias не заменяет проверку подписи восстановленным приватным ключом.

Восстановление проверено 28.09.2026 командой `scripts/Test-SigningRecovery.ps1`: ключ импортирован в отдельный PKCS12 под новым случайным паролем, им подписан тестовый APK; apksigner подтвердил тот же SHA-256 сертификата. Временные приватные файлы удалены, исходный ключ сохранён. Это проверка восстанавливаемости, а не независимая резервная копия на другом носителе. Переносимый экспорт с паролем владельца остаётся его операционной задачей.

В сайт и раздачу попадают только APK и его SHA-256; Git хранит исходники и SHA-256. Ни PKCS12, ни DPAPI-файл, ни пароль туда не входят. Потеря постоянного ключа препятствует совместимому обновлению уже установленных публичных APK.
